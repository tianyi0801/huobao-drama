# 分镜拆解指南

## 核心定义：分镜段落

一个分镜 = 一个 **分镜段落**（segment）= 一个视频生成任务。

- 新段落采用内容驱动的 **4—12整数秒**，不设5秒目标、不扩大到15秒；这是本地稳态策略，不是官方能力上限或质量保证
- 默认一个连续镜头、一个主要行动，固定或简洁单一运镜；只有叙事确需换景别/对象时切镜，最多2个子镜头、每个至少2秒，不为凑长切镜
- 一个段落只在一个场景内发生（`scene_id` 为段落绑定）。同场景相邻段落沿用机位、人物位置、门窗/家具和主光的相对关系，不反复建立空间
- 新拆分优先单人/双人镜头；双人同焦平面，逐人写清位置、距离、朝向、衣着识别点和独立动作，保留所有剧情角色的可辨认脸部
- 新拆分每个生成片段优先一个主要说话人，同角色可连续多句但须时间充足，换人优先新片段；这不是官方“每Shot单说话人”硬限制，不用于改写已有镜头或删对白
- 直接进入当前行动，以正常速度推进；不反复补建立镜头、抬头吸气、慢动作或尾部定格。剧情要求的停顿与表演保留，不靠通用动作填时长

## 拆分流程（四步）

1. 调用 `read_storyboard_context` 读取剧本、角色、场景、道具和已有分镜摘要；按保存工具现有schema填写字段
2. **因果与节拍**：先在内部理清前置状态 → 当前行动/谁对谁说原句 → 即时结果和下一段承接，再按叙事转折与说话人变化拆分。同一因果链可跨相邻段落，承接已有位置与动作；规划不得进入H3正文，也不新增规划字段
3. **时长估算**：按各段自然发话、动作、必要停顿及合理重叠估算，不设字数折算总时长或段数配额；超过12秒则在自然语义/动作边界继续下一段，不删台词或剧情
4. **设计与保存**：用 description 的 `【镜头N】` 描写可见行动及原句对白，按 video-prompt 权威技能同步产出视频字段。每批最多2段、每轮一次 `save_storyboards`；整集重拆仅首批 `replace_existing: true`，后续追加；明确增量修改不清空旧分镜，全部保存成功后完成

## 节奏分层时长

按段落功能确定时长，不要一刀切：

| 段落类型 | 时长 | 说明 |
|---|---|---|
| 短反应 | 4 秒 | 原剧情中的短反应，立即进入状态变化 |
| 普通对白 | 5—8 秒 | 按原句自然发话，同角色可连续多句 |
| 连贯动作 | 6—10 秒 | 正常速度的连续行动，不插入重复准备动作 |
| 长对白 | 10—12 秒 | 留足原文停顿，不强行压短或凑满12秒 |

以完成原内容所需时间为准，这些区间是内容参考，不是配额。无论段落类型，新拆分均保持4—12整数秒，不删剧情以满足区间。

## 自然发话与动作估时

中文对白按**4.5—5.5字/秒**估算，一般增加**0.4—0.8秒总缓冲**；情绪停顿按原文单独考虑，不对每句或每个动作重复加缓冲。其他语言使用自然发话时长，不套中文字速。

动作与对白可合理同时发生时，按重叠后的真实总时长估算；必须先后发生时累计，避免一律相加或强行重叠。超出12秒则按原句语义或动作承接自然拆到下一段，保留全部台词与动作，不补通用停顿、慢动作或收尾定格。

## 镜头要素

1. **镜头标题**：3-5字概括段落核心内容（如"噩梦惊醒"）
2. **时间**：具体时分 + 光线描述
3. **地点**：场景完整描述 + 空间布局 + 环境细节
4. **景别**：段落内主导景别；多景别段落写组合，如"中景+特写"
5. **角度**：平视/仰视/俯视/侧面/背面
6. **运镜**：固定/推镜/拉镜/摇镜/跟镜/移镜（段落内不同子镜头可不同）
7. **画面描述** `description`：在 `【镜头1】…【镜头2】…` 下先写可见行动的完整句，再以句号或换行分开写 `角色原名说：「原句」`；角色名精确匹配业务原名、不翻译，台词逐字完整保留，不将动作文本混入说话人名称。旁白只保留已有内容并写 `旁白：「原句」`
8. **即时结果与承接**：将段落结尾后果和下一段已成立的状态写在 `description` 中，不新增 `result` 或因果规划字段
9. **氛围** `atmosphere`：光线 + 色调 + 环境氛围，不据此新增配音或配乐
10. **时长** `duration`：4—12整数秒，足够自然发话与行动，不按目标时长凑长
11. **场景关联**：若能匹配已有场景，必须填写 `scene_id`
12. **角色关联**：填写 `character_ids`，绑定当前段落涉及的 0 到多个角色
13. **道具关联**：填写 `prop_ids`，绑定当前段落出现的关键道具（0 到多个）

## 场景关联规则

- 优先使用 `read_storyboard_context` 返回的 `scenes`
- `location + time` 可明确匹配时，必须回填正确 `scene_id`
- 不要凭空生成不存在的场景 ID
- 如果剧本内容明显落在已有场景中，不要重复创造新场景描述

## 角色绑定规则

- `character_ids` 必须从 `read_storyboard_context` 返回的角色列表中选择
- 一个段落可以没有角色，也可以绑定多个角色
- 只要段落里有明确出场、被看见、发生动作或说话的角色，都应绑定进去
- 纯环境段落、空镜、物件特写可以传空数组

## 道具绑定规则

- `prop_ids` 必须从 `read_storyboard_context` 返回的道具列表（`props`）中选择
- 道具被角色使用、交接、特写，或在画面中明显可见且对叙事有意义时，必须绑定到该段落
- 道具特写段落（无角色）也应绑定道具，`character_ids` 可为空
- 与剧情无关的背景物品、场景陈设不要绑定；没有道具出现的段落传空数组
- 绑定的道具会作为视频生成的参考图（白底单品图），保证道具外观跨段落一致

## 质量要求

- 用 `description` 的 `【镜头N】` 写清前置状态、逐人行动/对谁说原句、即时后果及承接；旁白只保留原有内容。镜头标记仍是后续视频唯一镜头来源，不能由单话者经验自行增删
- 按 video-prompt 权威技能生成官方六节英文说明正文，台词/歌词/可见文字保持原语言；格式、引用图号、Subject/Sx、声音与视频风格细则不在本技能重复定义
- 重写已有段落保留 duration、镜头数、全部动作与对白，已有多说话人逐句明确主体ID，不用新稳态策略删改内容
- 保存前逐句检查角色、顺序、完整原句与次数，并检查动作因果、实际时间和相邻段落空间承接；只使用既有工具schema，不创建 result、image_prompt、bgm_prompt、sound_effect 等字段
- 如需增量调整，调用 `update_storyboard` 修改具体段落，不清空整集

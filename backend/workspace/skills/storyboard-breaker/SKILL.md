# 分镜拆解指南

## 核心定义：分镜段落

一个分镜 = 一个 **分镜段落**（segment）= 一个视频生成任务。

- 本地 H3 调优环境：RTX 4060 Ti 8GB 显存、32GB 内存；先降低画面复杂度，不把硬件配置写成模型质量保证
- 每个段落时长 **4-12 秒，目标 5 秒**，默认 **1 个连续镜头、1 个主要动作**，固定机位或缓慢单一运镜
- 只有叙事确需换景别/对象时才切镜，最多 2 个子镜头，每个至少 2 秒；不要为了凑段数切镜
- 一个段落只发生在一个场景内（`scene_id` 是段落级绑定）
- 新拆分优先单人/双人镜头；双人均处于同一焦平面，脸部清晰可辨，写清每人左右位置、距离、朝向、服装识别点与独立动作，不把配角写成虚化背景
- 复杂多人戏拆到相邻段落，不漏剧情角色；同一段落内动作与台词按自然时序衔接，不塞入多次说话轮换

## 拆分流程（四步）

1. 调用 `read_storyboard_context` 读取剧本、角色、场景、道具、已有分镜摘要
2. **节拍识别**：先识别叙事节拍与转折点，节拍边界切段。同一因果链可拆成连续相邻段落，通过空间锚点、人物位置与动作承接保持关系；单段时长、对白容量和低复杂度优先，不为凑完整因果链塞入多人动作与反应切镜
3. **时长估算**：剧本字数 ÷ 500 × 60 得到秒数，仅作为粗略软参考，不设总段数或±20%硬指标。实际总时长按各段自然发话、动作与停顿所需时长累加；宁可多切一段，也不要删剧情或超过12秒
4. **设计低复杂度镜头**：默认单镜头完成一个动作或一句短对白，只有叙事必要才切镜。为每段补全完整字段后分批调用 `save_storyboards` 保存，每批最多2段，每轮仅一次保存调用；整集重拆仅首批带 `replace_existing: true`，后续追加；明确的增量修改不清空旧分镜。全部批次保存成功后才能完成

## 节奏分层时长

按段落功能确定时长，不要一刀切：

| 段落类型 | 时长 | 说明 |
|---|---|---|
| 过渡段 | 4-5 秒 | 赶路、空镜、环境建立、转场 |
| 叙事段 | 5-8 秒 | 常规剧情推进、对话 |
| 长对白或缓慢动作段 | 9-12 秒 | 按剧情与自然语速延长，用停顿、表情和单一动作强化，避免频繁切镜 |

> 本轮采用5秒优先、12秒段落上限的低复杂度策略；绝不能超过12秒，也不要强制凑满12秒。这不是 H3 模型时长能力的硬上限，剧情完整与自然语速优先于段数估算。

## 台词容量（硬规则）

**段内台词与旁白总字数（写在 description 中的部分）≤ (duration − 2) × 4.5 字/秒**

即 5 秒约 13 字、12 秒约 45 字。装不下的台词必须拆到下一个段落，不允许把演不完的台词塞进一个段落。

## 镜头要素

1. **镜头标题**：3-5字概括段落核心内容（如"噩梦惊醒"）
2. **时间**：具体时分 + 光线描述
3. **地点**：场景完整描述 + 空间布局 + 环境细节
4. **景别**：段落内主导景别；多景别段落写组合，如"中景+特写"
5. **角度**：平视/仰视/俯视/侧面/背面
6. **运镜**：固定/推镜/拉镜/摇镜/跟镜/移镜（段落内不同子镜头可不同）
7. **画面描述** `description`：按 `【镜头1】…【镜头2】…` 逐子镜头描述观众实际看到和听到的内容——画面（谁 + 具体动作 + 肢体细节 + 表情）写在前；该子镜头有台词时以「角色名说：「台词」」写在对应 `【镜头N】` 内，旁白写「旁白：内容」
8. **画面结果** `result`：段落结尾的即时后果 + 视觉细节
9. **氛围** `atmosphere`：光线 + 色调 + 声音 + 整体氛围
10. **时长** `duration`：整数秒，目标 5 秒，允许 4-12 秒，且满足台词容量上限
11. **场景关联**：若能匹配已有场景，必须填写 `scene_id`
12. **角色关联**：填写 `character_ids`，绑定当前段落涉及的 0 到多个角色
13. **道具关联**：填写 `prop_ids`，绑定当前段落出现的关键道具（0 到多个）

## 场景关联规则

- 优先使用 `read_storyboard_context` 返回的 `scenes`
- `location + time` 可明确匹配时，必须回填正确 `scene_id`
- 不要凭空生成不存在的场景 ID
- 如果剧本内容明显落在已有场景中，不要重复创造新场景描述

## 角色绑定规则

- `character_ids` 必须从 `read_storyboard_context` 返回的角色列表中选择
- 一个段落可以没有角色，也可以绑定多个角色
- 只要段落里有明确出场、被看见、发生动作或说话的角色，都应绑定进去
- 纯环境段落、空镜、物件特写可以传空数组

## 道具绑定规则

- `prop_ids` 必须从 `read_storyboard_context` 返回的道具列表（`props`）中选择
- 道具被角色使用、交接、特写，或在画面中明显可见且对叙事有意义时，必须绑定到该段落
- 道具特写段落（无角色）也应绑定道具，`character_ids` 可为空
- 与剧情无关的背景物品、场景陈设不要绑定；没有道具出现的段落传空数组
- 绑定的道具会作为视频生成的参考图（白底单品图），保证道具外观跨段落一致

## 质量要求

- `description` 按 `【镜头1】` 写清逐人位置、可见脸部、动作和原句对白；默认不再补 `【镜头2】`，旁白仅保留剧本原有内容
- `video_prompt` 使用 MiniMax 官方 Ref2VA 六节结构（subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music），正文英文；每个可见配角都有独立 <Subject N> 与画面动作，不用泛称替代
- 原句对白写成 <d>[Chinese] 原句</d>，只在 detailed_description 对应 Shot 写一次，并给实际发声者分配稳定 (Sx)；overall_soundscape 只写 1—4 句英文环境音与物理声，不列说话白名单、不重复对白
- non_diegetic_music 无配乐时写 N/A，不要根据 atmosphere 自动添加配音或音乐
- 字段按保存工具 schema 填写，不要求不存在的 image_prompt、bgm_prompt、sound_effect
- 如需增量调整，调用 `update_storyboard` 修改具体段落，不清空整集

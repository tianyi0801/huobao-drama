# 分镜拆解指南

## 核心定义：分镜段落

一个分镜 = 一个 **分镜段落**（segment）= 一个视频生成任务。

- 段落承载一个戏剧节拍或完整小回合，尽量把 **铺垫—发生—反应** 放在一起，而不是每个动作、每句话都另建一个任务
- 新段落时长 **4-12 整数秒**，先设计叙事内容再确定时长，没有固定目标秒数；硬件配置不决定镜头语法
- 通常 **2—4 个子镜头**可作为叙事手法参考，按信息变化、动作、视线或话轮切镜；不是数量配额，也不强制等分，完整调度可以用一个长镜头
- 一个段落只发生在一个场景内（`scene_id` 是段落级绑定）；总时间轴连续无重叠、无空缺，严格等于 duration
- 景别、角度与运镜服务叙事，可用建立镜头、正反打、过肩、动作/道具特写、听者反应、推拉跟移和有动机的焦点转移；不把双人戏锁在平视同焦中近景
- 逐镜说明关注主体、人物相对位置、视线与动作；需要辨认身份或表情时脸部清晰，允许合理背影、遮挡及景深变化，不遗漏有剧情作用的配角

## 拆分流程（四步）

1. 调用 `read_storyboard_context` 读取剧本、角色、场景、道具、已有分镜摘要
2. **节拍识别**：识别开场、触发、高潮、收尾与转折点，重大节拍边界切段。同一因果链的铺垫—发生—反应优先放在同段，用动作、视线与听者反应体现人物关系；只有超出任务时长范围才在自然话轮或动作衔接处拆段
3. **镜头设计与时长分配**：先按建立关系、动作细节、关键信息与反应设计子镜头，再分配不等长时间轴。总时长按实际表演进程估算：可同时发生的对白、动作和反应不重复相加，不为凑秒数补空镜或停顿；字数只作语速参考，不设总段数或±20%配额
4. **分批保存**：每段补齐 description 与 video_prompt 等字段后调用 `save_storyboards`，每批最多2段，每轮仅一次保存调用（这是保存批量，不是子镜头数量限制）；整集重拆仅首批带 `replace_existing: true`，后续追加；明确的增量修改不清空旧分镜。全部批次保存成功后才能完成

## 叙事节奏与镜头手法

- **过渡**：用最少的画面交代新空间与关系；信息清楚即推进，不重复空镜、站立或慢推
- **动作—细节—反应**：中景交代动作，关键物件/手部特写呈现信息，人物反应展示结果；这些可在同段形成完整回合，不必每个环节另占一个生成任务
- **对话**：双人建立镜头明确关系，再按说话者、听者反应与话轮切正反打或过肩；允许对白延续到听者反应，保持说话人明确，不变成新增画外人声
- **景别递进与爆点**：常规信息迅速推进，关键揭示或情绪转折用特写和有动机的停留强调；重要表演适合长镜头时不强行切碎，也不要所有镜头一样长
- **切镜依据**：信息变化、动作衔接、视线与话轮，而不是定时切换。短促插入/反应可少于2秒，但必须看清；不设置子镜头数量配额或统一最短秒数，不机械等分
- **空间连续**：保持场景布局、光源、轴线和动作状态；允许换景别、机位与构图，逐镜说明人物相对位置与视线，禁止无交代跳轴或重新编造场景

> 新段落仍在4-12整数秒的应用范围内，先设计内容再定时长，没有固定目标秒数。这不是 H3 模型能力声明；超出范围时在自然话轮或动作承接处拆段。

## 自然对白与表演时长

中文约4—5字/秒只作估算，其他语言按实际语速、情绪和必要停顿分配。对白、动作与听者反应可并行，不逐镜机械预留2秒，不用空停顿补齐时长。

原句必须逐字保留，不能用异常语速赶完；确实超出任务范围的长句在自然语义处分到相邻段落，不删台词或把一个完整小回合过度拆碎。

## 镜头要素

1. **镜头标题**：3-5字概括段落核心内容（如"噩梦惊醒"）
2. **时间**：具体时分 + 光线描述
3. **地点**：场景完整描述 + 空间布局 + 环境细节
4. **景别**：段落内主导景别；多景别段落写组合，如"中景+特写"
5. **角度**：平视/仰视/俯视/侧面/背面
6. **运镜**：固定/推镜/拉镜/摇镜/跟镜/移镜（段落内不同子镜头可不同）
7. **画面描述** `description`：按 `【镜头1】…【镜头2】…` 逐子镜头描述观众实际看到和听到的内容——画面（谁 + 具体动作 + 肢体细节 + 表情）写在前；该子镜头有台词时以「角色名说：「台词」」写在对应 `【镜头N】` 内，旁白写「旁白：内容」
8. **画面结果** `result`：段落结尾的即时后果 + 视觉细节
9. **氛围** `atmosphere`：光线 + 色调 + 声音 + 整体氛围
10. **时长** `duration`：4-12整数秒，按节拍与自然表演确定，先内容后时长，不强制固定秒数
11. **场景关联**：若能匹配已有场景，必须填写 `scene_id`
12. **角色关联**：填写 `character_ids`，绑定当前段落涉及的 0 到多个角色
13. **道具关联**：填写 `prop_ids`，绑定当前段落出现的关键道具（0 到多个）

## 场景关联规则

- 优先使用 `read_storyboard_context` 返回的 `scenes`
- `location + time` 可明确匹配时，必须回填正确 `scene_id`
- 不要凭空生成不存在的场景 ID
- 如果剧本内容明显落在已有场景中，不要重复创造新场景描述

## 角色绑定规则

- `character_ids` 必须从 `read_storyboard_context` 返回的角色列表中选择
- 一个段落可以没有角色，也可以绑定多个角色
- 只要段落里有明确出场、被看见、发生动作或说话的角色，都应绑定进去
- 纯环境段落、空镜、物件特写可以传空数组

## 道具绑定规则

- `prop_ids` 必须从 `read_storyboard_context` 返回的道具列表（`props`）中选择
- 道具被角色使用、交接、特写，或在画面中明显可见且对叙事有意义时，必须绑定到该段落
- 道具特写段落（无角色）也应绑定道具，`character_ids` 可为空
- 与剧情无关的背景物品、场景陈设不要绑定；没有道具出现的段落传空数组
- 绑定的道具会作为视频生成的参考图（白底单品图），保证道具外观跨段落一致

## 质量要求

- `description` 按实际设计的 `【镜头1】【镜头2】…` 逐镜写清景别、位置、视线、动作、原句对白和必要的发话时段；各镜头有新的叙事信息，避免一个动作一段或无意义停顿，旁白仅保留剧本原有内容
- `video_prompt` 使用六节结构，【镜头N】与 [Shot N] 的顺序、切镜点和动作对应；每个可见配角有独立 Subject，只使用实际存在的身份参考，不用泛称替代
- 原句对白只在 detailed_description 对应 Shot 写一次；overall_soundscape 仅列说话白名单及环境/动作声，每人仅在自己的对白时段发声，无台词或未轮到发话者闭口；无对白/旁白时明确无任何人声，无原旁白时不新增旁白、解说、画外人声和哼唱
- non_diegetic_music 默认“无背景配乐、无歌声”，不要根据 atmosphere 自动添加配音或音乐
- 字段按保存工具 schema 填写，不要求不存在的 image_prompt、bgm_prompt、sound_effect
- 如需增量调整，调用 `update_storyboard` 修改具体段落，不清空整集
